# 开发卡片（Development Cards）

开发卡片是"顶层创意 / 细节构想 → 评审 → 排期 → 实现 → 回填"的唯一入口。

卡片解决的问题：创意先于任务存在时，用什么形式落字、怎么防止口头设计
丢失或跳过设计直接开工。**卡片不等于派工**——沿用 §0-first 纪律：排期时
卡片冻结为 `AGENT_CONTEXT/TASKS/` 任务书的 §0 边界，任务书才是开工
边界；没落字的卡片只是创意，任何人可以据此来催评审，但不能据此开工。

## 谁可以提

用户（顶层创意）、协调人、A / B（细节构想），任何人任何时候。一卡一事；
拆不动的复合构想先提总卡，评审时拆子卡并在总卡登记子卡编号。

## 文件与命名

- 目录：`AGENT_CONTEXT/CARDS/`
- 命名：`CARD-<四位序号>-<短横线标题>.md`（序号在 INDEX 登记，递增不复用）
- 新卡从 `TEMPLATE.md` 复制起草；状态变更同步 `INDEX.md`

## 生命周期

```text
草案 → 评审中 → 已排期（指向任务书）→ 已实现（指向 PR，回填结果/学习）
                ↘ 已否决（写明原因，保留不删）
```

- **草案**：必填项（闭环环节 / 权限等级 / 隐私面 / 验收草案）填全即可转"评审中"。
- **评审**（协调人门槛三问，任一不过退回补全）：
  1. **闭环环节是否成立**——增强 看到 / 记住 / 理解 / 规划 / 行动 / 学习
     的哪一环、怎么增强；说不清环节的展示型功能应延后（AGENTS.md §1）。
  2. **权限等级是否标注**——高风险、不可逆、对外沟通、代表用户决策的
     动作是否默认 ≥ Level 2（AGENTS.md §3）。
  3. **隐私面四要素是否齐**——采集什么 / 是否上传（最小化论证）/
     谁可访问 / 如何删除。
  顶层创意另需对齐阶段优先级（AGENTS.md §8，P0-P3）；不属于当前阶段的
  转"暂缓"并在卡片记原因，不算否决。
- **排期即冻结**：排期时生成任务书，任务书 §0 引用卡片编号；卡片状态改
  "已排期"并链接任务书。此后的范围变更走任务书修订；卡片只追加一行
  "范围变更记录"。
- **实现回填**：对应 PR 合并后回填实际结果、偏差与学习（对齐
  Observe Result → Update State / Memory → Re-plan）；学习点若影响
  长期约定，同步 `DECISIONS.md` 并在"决议记录"回链。
- **否决**：写明否决原因与裁定人，卡片保留不删，便于追溯；同类创意
  再提时必须先回应上一次否决原因。

## 与现有机制的关系

- `GOALS.md` 是产品构想参考（非规范）；卡片是把其中可执行构想落地的
  中间层。
- 任务书（`AGENT_CONTEXT/TASKS/`）承接排期后的卡片；任务书 §0 验收
  以卡片"验收草案"为底冻结。
- `DECISIONS.md` 记录评审产生的长期约定；卡片"决议记录"字段回链。
- 本机制不替代 issue / PR：实现过程仍走分支 + 互审 + PR 合并。
