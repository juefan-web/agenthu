## 3. B-r2 契约面的服务端可实现性

- **字段镜像**：B §1 逐字段镜像 A §4 的 DTO 集，服务端均可实现，无缺发
  字段。nullable/optional 纪律（`?` = 必有可空 → `.nullable()` 必填键）
  与服务端"恒发 null"的发射约定一致；恒发字段同批进 Zod + OpenAPI 的
  sequencing 与 A 侧无冲突。
- **manifest 消费集**（schema_version/graph_version/snapshot_at/generation/
  family_counts/entries/excluded_categories）⊆ A §3 manifest 字段，可实现。
- **recover 三件套**（原 JWT 身份、原 client_request_id、同请求摘要）：
  服务端可实现——停用身份走专用依赖（验签 + 用户匹配、仅此路由放行
  is_active=false），10 分钟交付缓存窗口与 A §4 一致。防枚举要求已由
  A-r2 §4 补齐（统一 404、按身份+按 IP 双限流、digest 高熵第二因子、
  无时延 oracle、能力 ≥128-bit、不进日志）；B 侧"capability 不进 URL/
  日志/剪贴板自动复制/遥测"与之互补，无缺口。
- **preview_digest 绑定强度**：设计上 digest 不是安全边界——confirm 在
  事务内复核 target/graph_version/data_generation/影响集，digest 是防
  "拿错 preview 确认"的回显绑定。绑定 user+target+graph_version+
  data_generation+影响集+内容版本摘要，强度足够；实现上内容版本摘要可
  复用 Memory.content_revision（models/memory.py，M4 已维护的 sha256）
  聚合，代价低。要求 digest 只含哈希不含正文——A-r2 §2.1 已有"审计不存
  正文"，digest 同口径。
- **GrantScopeCatalog**（§5）：`GET /v1/permissions/scope-catalog` 可由
  ACTION_POLICY + 工具注册表（register_tool 元数据已含 action/level/
  scope_validator）派生，`implemented:false` fail-closed 不显示与
  A-r2 §8-4"不支持渠道不能存有效 grant"同向。要求 channels[] 只列
  实际可执行渠道枚举（A-r2 §8-4 裁定项），不展示超能力面。
- **owner_key = backend origin + server user_id**：与 A §7 同步代际/无主
  队列规则相容；Backend 逐项校验抑制/目标/代际的重基规则双方文本一致。
- **B 侧事实抽查**：三层存储全部对码——queue.ts:4-5（`agenthu.event-queue`
  /`.corrupt`）、focus/draft.ts:25（`agenthu.focus-draft`）、lib.rs:157/273
  （QueueDb + offline.sqlite3，payload 为用户内容面）、vault.rs
  （campus/token 具名槽，`{slot}-vault-v1` 命名）；App.tsx:93
  queryClient.clear() 在退出钩子。三层均无 owner 维度，B 的判断成立。

## 5. 给 B 的建议（不阻塞，编号供回执）

1. §2 状态表 QUEUED/RUNNING 行的查询对象：账号删除场景 owner 认证
   将在确认后失效（401），COMPLETED 的可见来源只剩 receipt 视图——
   建议明示"账号删除的状态查询走 receipt 轮询，operation 轮询仅适用
   source/memory"，与 A-r2 §2 手动重试范围收紧对齐。
2. §1 "无 capabilities 时显示…"与 minimum_client_version 只控显隐——
   建议补一句旧客户端（不识 /v1/data）不因此隐藏旧 DELETE 的原语义
   入口（A §7：旧入口保持原语义，防用户以为无处可删）。
3. §5 GrantScopeCatalog 建议加 catalog_version 变更纪律（服务端加
   action/channel 必须升版本，客户端按版本缓存失效），避免目录漂移
   又造一个 drift 面。
4. §3 本机清理状态机 `verified` 判据与 E7-7 的"WAL 真实清除证据"对齐时，
   建议把"证据"定义为可复跑的检查命令输出（而非一次性手工确认），
   便于 E7 双轮同规格。
5. §8 修订账"删除/不认同（1）"实际是收紧而非删除——建议措辞区分
   "收紧保留"与"删除"，避免协调人归档时误读 r1→r2 的语义变化面。
